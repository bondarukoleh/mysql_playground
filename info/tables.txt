NULL value
NULL in sql means - "Value is unknown" - doesn't mean zero!
in desc table there is NULL column - if there is YES, then value or row can be NULL, means you can leave this 
row value unset - with NULL. You can even "insert into table_name() values()" - and it will set NULL from values
in whole row.
To specify that value cannot be null - we can set NOT NULL into a column data type when we're crating table.
mysql$>create table users(name varchar(15) not null, age int not null);
And in NULL column you'll see NO value.
If we try to leave some value unset in this table - we'll get warning, and we'll have 0 as a default value in table,
for example. OR if we try to set NULL manually - we'll get error.
Same thing with string, - default for it is empty string, not null.

DEFAULT VALUE
There is Default column in desc table, so if value is unset - default value comes into play.
We can manage it when creating table.
mysql$>create table cats(name varchar(15) default 'unnamed', age int default 1, lives int default 9)

KEY
          cats
+---------+------+-------+
| name    | age  | lives |
+---------+------+-------+
| Blue    |    5 |     9 |
| Blue    |    5 |     9 |
+---------+------+-------+

In this case, we have two different cats but with the same data. And we can't unify them.
The Query will return the first cat, and that's all.
So to solve this, we need to add some ID to cats.
And there is a term for this - Primary key. This is a unique identifier for row of data.

create table unique_cats(cat_id int not null, name varchar(15) not null default 'unnamed',
 age int not null default 0, primary key(cat_id));

will create table with unique identifier;

desc unique_cats;
+--------+-------------+------+-----+---------+----------------+
| Field  | Type        | Null | Key | Default | Extra          |
+--------+-------------+------+-----+---------+----------------+
| cat_id | int(11)     | NO   | PRI | NULL    | auto_increment |
| name   | varchar(15) | NO   |     | unnamed |                |
| age    | int(11)     | NO   |     | 0       |                |
+--------+-------------+------+-----+---------+----------------+

After that we cannot add "insert into unique_cats(name, age, cat_id) values('Blue', 5, 1);" twice.
We will be forced to set a unique identifier to cat_it.
We can also set name, or age a primary key, to make it unique.

To not set cat_id each time manually, we cat set AUTO_INCREMENT to it.
create table unique_cats(cat_id int not null auto_increment primary key, name varchar(15) not null default 'unnammed',
 age int not null default 0);
sic! primary key - not in the end like primary key(cat_id), but after cat_id in a columns section of the query.

UNIQUE
We can make come column value unique, that means it cannot be duplicated. Sort like PRIMARY KEY, but if it is
a massive user name -> so search it will be more complex and slower.
create table table_name(colunm_name VARCHAR(100) UNIQUE);

PRIMARY KEY unique combination.
If you need to set some unique combination of column values - we can set it via PRIMARY KEY
create table table_name(
  colunm_name1 VARCHAR(100),
  colunm_name2 VARCHAR(100),
  PRIMARY KEY(colunm_name1, colunm_name2)
); -> and there is no chance these two values will be duplicated. It means two rows with the same colunm_name1,
 colunm_name2 values cannot be added.
